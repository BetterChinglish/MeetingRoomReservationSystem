## 一、环节目标与设计总纲

### 1.1 环节目标
本环节（环节 2：原型设计）的核心目标是依据已定稿的产品需求说明书（PRD 总纲及 5 份专业分册），构建**高保真、纯单文件、支持无缝离线与在线双模式运行的可交互 Web 原型**。

通过该原型，实现以下关键业务价值：
1. **反向验证需求**：以真实、直观的人机交互界面，验证 PRD 中定义的用户角色权限、半开区间冲突判定、状态机自然流转与数据看板统计口径的完整性与自洽性。
2. **消弭人机歧义**：在进入环节 3（规格编写）与环节 4（编码实现）之前，固化前后端字段约定、组件结构、用户操作路径与反馈提示，避免后期返工。
3. **沉淀视觉与组件规范**：确立规范的企业级 Element Plus 蓝白清爽后台风格，为前端 Vue 3 工程提供标准化的组件选型、间距节奏与图表色彩体系。

### 1.2 设计原则
- **契约严格对齐**：页面字段、状态机枚举、主数据命名与权限规则 100% 映射 PRD 分册 01~05。
- **真实数据闭环**：内置完整的组织架构、会议室主数据及多状态预置预约，支持实时新增、取消、提前结束并实时驱动看板图表联动刷新。
- **免构建极速体验**：单文件 `prototype.html`，无需复杂的 Node.js/Vite 构建流程，任何浏览器双击即开即可交互。

### 4.2 页面一：预约列表页（Reservation List）

预约列表是全员使用频次最高的业务页面，承载信息检索、状态监视与生命周期流转触发。

#### 4.2.1 组合筛选区
- **会议室筛选**：下拉选择，展示会议室名称与容纳人数，支持一键清空。
- **日期筛选**：单日日期选择器，支持指定查看某天排期。
- **部门筛选**：按预置 5 大部门（研发部、产品部、市场部、行政部、财务部）筛选。
- **状态筛选**：四值枚举（全部 / 未开始 PENDING / 进行中 ACTIVE / 已结束 ENDED / 已取消 CANCELLED）。
- **快捷单选视图组**：
  - `全量预约`：全员公开可见所有记录（符合 PRD RV-5）。
  - `仅看本人预约`：一键过滤当前模拟登录人的预约（员工张伟仅看张伟，管理员李强仅看李强）。
  - `今日预约`：快速定位当前日期的会议。
  - `当前进行中`：快速定位正在开会的场地。

#### 4.2.2 表格数据列与视觉设计
| 列名 | 呈现规范 | 交互/业务说明 |
| :-- | :-- | :-- |
| **预约编号** | `#1001` 等宽字体 | 唯一业务主键 |
| **会议室** | 标题粗黑，副标题灰色位置与容量 | 例：`第一会议室` / `A 座 3F-301 (10人)` |
| **会议主题** | 500 字重，超长省略并带 Tooltip | 展现会议业务实质 |
| **预约日期** | `YYYY-MM-DD` 表格数字 | 排序支持 |
| **时段与时长** | 主文本 `09:00 ~ 10:30`，副文本 `共 90 分钟` | 时长由 `calcDurationMinutes` 计算 |
| **预约人** | 姓名，若是本人带蓝底 `我` 标签，附部门名称 | 身份直观标识 |
| **即时状态** | 状态徽标胶囊（含动态微交互） | 详见下方状态视觉规范 |
| **操作** | 区分角色的动态文字按钮 | 详见下方权限矩阵 |

#### 4.2.3 状态徽标视觉规范
- **未开始 (PENDING)**：浅蓝背景 `#eff6ff` + 品牌蓝边框与文字 `#2563eb`。
- **进行中 (ACTIVE)**：浅绿背景 `#ecfdf5` + 翠绿文字 `#059669` + **独创呼吸脉冲绿点动效**（通过 CSS keyframes 持续轻量扩散，直观呈现“会议正在进行”）。
- **已结束 (ENDED)**：浅灰底 `#f1f5f9` + 石板灰文字 `#64748b`。
- **已取消 (CANCELLED)**：浅红底 `#fef2f2` + 玫瑰红文字 `#dc2626`。

#### 4.2.4 角色操作权限与弹窗确认矩阵
- **未开始 (PENDING) 预约**：
  - *当前为员工且是本人* 或 *当前为管理员*：显示红字「取消预约」（管理员显示「取消(管理员)」）。点击触发二次确认弹窗：
    > *“确定取消【第一会议室】的预约‘核心架构复盘’(09:00~10:30)吗？取消后该时段将被立即释放供其他人预约。”*
    点击确定后，状态瞬时流转为 `CANCELLED`，气泡提示成功，该时段立即在表单中重新变为可选。
  - *当前为员工且非本人*：显示灰字「只读 (他人预约)」，按钮禁用，严格防范越权。
- **进行中 (ACTIVE) 预约**：
  - *当前为员工且是本人* 或 *当前为管理员*：显示黄字「提前结束」（管理员显示「提前结束(管理员)」）。点击触发二次确认弹窗：
    > *“确定提前结束正在进行的会议‘双十一营销推广’吗？结束后状态将变更为‘已结束’。按PRD规则，该时段仍完整归档计入统计。”*
    点击确定后，状态流转为 `ENDED`，气泡提示成功。
  - *当前为员工且非本人*：显示灰字「进行中 (只读)」，禁用点击。
- **已结束 (ENDED) / 已取消 (CANCELLED)**：统一显示 `— 已归档 —`，禁止任何流转（落实 PRD BR-RV-15 历史不可改写规则）。

### 4.3 页面二：发起预约表单页（Reservation Form）

预约表单用于员工创建会议，设计重点在于**防呆设计（Poka-Yoke）**与**冲突前置可视化检测**。

#### 4.3.1 表单字段结构
1. **预约会议室**：
   - 下拉项聚合展示：会议室名称、具体位置、额定容量。
   - 停用联动：若会议室 `status == DISABLED`，下拉项自动标记为 `已停用` 并禁用选择。
   - 选中后，下方实时卡片反馈该会议室的位置与容量详情。
2. **预约日期**：
   - 单日选择，限制仅能选择今日及未来日期，过去日期置灰禁止点击（落实 PRD BR-RV-04a）。
3. **预约起止时段**：
   - 采用两个联动下拉框（08:00 ~ 21:00，步长 30 分钟）。
   - 实时计算并高亮显示预计占用时长：`⏱️ 预计占用时长：90 分钟 (1.5 小时)`。
   - 防错校验：若结束时间早于或等于开始时间，立即飘红提示 `⚠️ 结束时间必须严格晚于开始时间！`。
4. **预约人**：
   - 自动绑定当前模拟登录人（如 `张伟 (emp001)`），设为 `disabled` 且追加标签 `当前登录人自动注入 · 不可篡改`（落实 PRD BR-RV-08 隐性需求）。
5. **预约部门**：
   - 默认带入当前登录用户所在部门，支持下拉选择。
6. **会议主题**：
   - 输入框，必填，限制 2~100 字符，右下角展示实时字数统计计数器。

#### 4.3.2 创新设计：当日排期时间轴看板（Timeline Schedule Grid）
在表单中央嵌入了一套**全景时间轴排期看板**（08:00 - 20:00，共 12 小时）：
- 轨道上方清晰标识：`第一会议室 在 2026-10-27 的占用排期`。
- **已有占用块（灰色）**：自动将当前会议室在目标日期的所有有效预约（PENDING/ACTIVE/ENDED）渲染在绝对坐标轨道上，悬停显示会议主题与预约人。
- **本次拟约预览块（条纹蓝）**：当用户在上方选择起止时间后，拟约时段以蓝白相间斜纹方块实时贴合在时间轴上！
- **冲突高亮动效（红色震颤）**：一旦与既有会议重合，拟约方块瞬间变为警示红底并产生轻微晃动提示，人机交互直观明确。

#### 4.3.3 实时冲突检测横幅（Conflict Detection Banner）
表单内含响应式冲突侦测引擎：
- **冲突状态**：显示 Element Plus 醒目错误告警盒（`type="error"`）：
  > `⚠️ 时段冲突告警：所选时段已被占用！与已有预约【核心架构双周敏捷复盘会】(09:00 ~ 10:30 · 预约人: 张伟) 时段重叠。请调整时间。`
  同时「确认提交预约」按钮置灰禁用，杜绝非法提交。
- **合规状态**：显示绿色成功告警盒（`type="success"`）：
  > `✅ 时段空闲检测通过：该会议室在目标时段内无排期重叠（符合 [start, end) 半开区间不相交规则），可安全提交预约。`
  提交按钮激活可用。

### 4.4 页面三：数据看板页（Data Dashboard）

数据看板供行政管理人员与全员全面洞察会议室资源利用率与部门活跃度。

#### 4.4.1 筛选与缓存控制
- **维度切换单选组**：
  - `按日期统计 (单日)`：激活单日日期选择器，默认今天。
  - `按月份统计 (单月)`：激活月份选择器，默认本月（`2026-10`）。
- **刷新按钮与缓存标记**：
  - 点击「刷新统计」，按钮呈现加载旋转，执行防抖后平滑更新，右侧悬挂 `Redis 缓存加速` 徽章，模拟服务端主动失效与回源逻辑。

#### 4.4.2 4 组核心 KPI 卡片
1. **有效预约总场次**：聚合统计选定范围内核准的预约总数（排除已取消项），单位：`场`。
2. **总占用时长**：聚合计算总时长，主值展示 `分钟`，副标签换算为 `小时`（例如：`780 分钟 (折合 13.0 小时)`），遵循原预约区间计算口径。
3. **纳入统计会议室**：展示全量主数据会议室数（`5 间`），说明标注 `全量主数据呈现 · 0场次不隐藏`。
4. **参与预约部门**：展示组织全量部门数（`5 个`）。

### 4.5 悬浮辅助工具：时间推进模拟器

位于原型右下角的轻量胶囊工具条：
- **时钟快进**：提供 `09:30`、`11:30`、`14:30`、`18:00` 四个典型时间点按钮。
