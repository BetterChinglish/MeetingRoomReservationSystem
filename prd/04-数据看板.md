## 1. 概述

系统为单位行政提供会议室预约情况的数据看板（仅 Web 端），用于直观掌握会议室资源占用情况与各部门预约活跃度。看板支持按 **日期** / **月份** 两个维度切换筛选，分类展示「各会议室的预约场次、占用时长」与「各部门的预约场次、占用时长」四组指标，并通过 ECharts 柱状图/堆叠图进行直观对比。

本分册定义：

- 看板入口与筛选维度（日期 / 月份切换）；
- 统计指标定义与计算口径（预约场次、占用时长，明确单位与排除规则）；
- 图表展示形式与规格（会议室场次对比、部门场次对比、占用时长对比/堆叠）；
- 空数据态、加载态、错误态的展示要求；
- 看板权限（员工与管理员均可查看，无管理操作）；
- 数据实时性与 Redis 缓存需求（缓存键、过期策略、失效时机）；
- 显性需求、隐性需求、业务规则、边界条件与验收标准。

## 2. 用户角色与权限（仅本领域相关）

| 能力 | 普通员工 EMPLOYEE | 管理员 ADMIN | 说明 |
| :-- | :-- | :-- | :-- |
| 进入数据看板页面 | ✅ | ✅ | 登录即可，无需额外授权 |
| 切换日期 / 月份维度 | ✅ | ✅ | 筛选条件对两类角色一致 |
| 查看各会议室预约场次 / 占用时长 | ✅ | ✅ | 不区分本人/他人，全员可见 |
| 查看各部门预约场次 / 占用时长 | ✅ | ✅ | 部门维度数据全员可见 |
| 导出看板数据 | ❌ | ❌ | MVP 不提供导出能力 |
| 配置/管理看板指标 | ❌ | ❌ | MVP 不提供指标配置 |

判定要点：

- 看板所有接口仅要求「已登录且 JWT 有效」，不要求 `role == ADMIN`。
- 看板不含任何写操作（无新增/编辑/删除），仅查询与统计。
- 看板数据范围不按当前用户过滤：员工与管理员看到的是同一份全量统计结果，不隐藏他人/他部门的预约数据（与「所有员工可查询所有会议室预约情况」一致）。

## 4. 隐性需求

原始需求未明写、但为保障看板可用与数据一致必须落实的需求：

1. **维度切换的默认值**：进入看板时需有合理默认筛选（日期维度默认「今天」；月份维度默认「本月」），不能要求用户先选择才能看到数据。
2. **筛选输入合法性校验**：日期维度限制单日选择；月份维度限制选择某个月（不指定日）；前后端均校验，非法输入返回 400 并提示。
3. **时区与日期边界**：日期/月份的起止边界以服务器所在时区（Asia/Shanghai）为准，避免跨时区导致漏算/重算。
4. **空数据态**：所选范围内无有效预约时，图表区与指标卡需展示空态（如「当前范围暂无预约数据」），而非空白或报错。
5. **加载态**：首次加载与切换筛选时展示 loading（骨架屏或 Element Plus `v-loading`），避免长时间白屏。
6. **错误态**：接口异常或缓存异常时展示错误提示与「重试」按钮，不阻塞页面其他部分。
7. **指标口径一致性**：看板统计口径需与预约列表的「有效预约」定义一致，已取消（CANCELLED）的预约不计入场次与时长。
8. **会议室/部门主数据联动**：看板的「各会议室」「各部门」应来自主数据表，包括当前没有任何有效预约的会议室/部门也应展示（场次为 0、时长为 0），以便对比资源利用情况，而非只展示有预约的实体。
9. **数值单位与精度**：占用时长需明确单位（分钟或小时），且图表轴标签、指标卡、Tooltip 均统一单位；避免出现「90 分钟」与「1.5 小时」混用造成误读。
10. **实时性预期**：看板数据允许短时延迟（秒级到分钟级），不强求与预约操作毫秒一致；通过 Redis 缓存 + 失效策略在性能与实时性间取舍。
11. **可读性与排序**：图表类别（会议室/部门）应有稳定排序（默认按场次降序，或按主数据顺序），切换维度时排序规则一致，避免图表跳动无规律。场次/时长并列时按 `room_id` / `dept_id` 升序作为稳定次级排序，保证相同主指标下类别顺序确定。（已按评审建议6补充）
12. **图表响应式**：看板在常见桌面分辨率下完整展示三组图表，窗口缩放时 ECharts 自适应 resize；MVP 仅 Web 端，不要求移动端适配。
13. **数字格式化**：场次 ≥ 1000 时使用千分位展示（如 1,200）；时长 > 60 分钟时，图表 Tooltip 与指标卡附加「X 小时 Y 分钟」友好展示；其余数值保持原样。（已按评审建议8补充）
14. **默认筛选值由后端权威下发**：「按日期」默认值（当前日期）与「按月份」默认值（当前月份）由后端按 Asia/Shanghai 时区返回，前端不本地推断，避免客户端时区差异导致默认范围不一致。（已按评审建议9补充）
15. **刷新按钮语义**：看板提供「刷新」按钮，点击后忽略 Redis 缓存直接回源数据库，并将最新结果回填缓存（覆盖旧值并重置 TTL）；3 秒内对相同参数的重复点击做防抖，避免连击压库。（已按评审建议2补充）

## 5. 业务规则

### 5.1 筛选维度

| 规则编号 | 规则 |
| :-- | :-- |
| DASH-01 | 看板提供两个互斥筛选维度：**按日期**（单日）、**按月份**（单月）。同一时刻只能启用其中一个维度。 |
| DASH-02 | 维度切换控件采用单选按钮组（Radio Group）或分段控件（Segmented），默认选中「按日期」。 |
| DASH-03 | 「按日期」维度下，日期选择器为单日选择（Element Plus `el-date-picker` type=date），默认值为服务器当前日期，可手动改为任意过去或未来日期（不限制范围，但未来日期通常无数据，展示空态）。 |
| DASH-04 | 「按月份」维度下，月份选择器为单月选择（type=month），默认值为服务器当前月份。 |
| DASH-05 | 维度切换时保留已选日期/月份的语义（如切换到月份维度时默认取已选日期所在月），避免用户重新选择。 |
| DASH-06 | 筛选条件变更后立即重新拉取数据并刷新图表；前端对相同参数的重复请求做防抖（默认 300ms）。 |

### 5.2 统计范围与有效预约口径

| 规则编号 | 规则 |
| :-- | :-- |
| DASH-07 | 仅统计 **有效预约**：`reservation.status != 'CANCELLED'` 的记录。`PENDING / ACTIVE / ENDED` 三种状态均计入。看板统一以数据库**存储态** `status` 判定，不走任何 `computeStatus` 实时推算（避免与列表/状态机口径产生偏差）。（已按决策B补充） |
| DASH-08 | 「按日期」维度：统计 `reserve_date == 所选日期` 的有效预约。 |
| DASH-09 | 「按月份」维度：统计 `reserve_date` 落在所选月份首日至月末的有效预约（含边界）。 |
| DASH-10 | 预约的归属部门以 `reservation.dept_id` 为准（预约发生时所在部门），不随预约人后续部门变更而回溯重算。 |
| DASH-11 | 预约的归属会议室以 `reservation.room_id` 为准。 |
| DASH-12 | 已删除/停用的会议室或部门仍可出现在历史统计中（按其主数据 id 关联展示名称）；主数据缺失时按「未知会议室/未知部门」兜底展示，不报错。 |

### 5.3 指标定义

| 规则编号 | 指标 | 定义 | 单位 | 计算口径 |
| :-- | :-- | :-- | :-- | :-- |
| DASH-13 | 会议室预约场次 | 在筛选范围内，该会议室的有效预约记录条数 | 场（条） | `COUNT(*)` where `room_id = ?` and `status != 'CANCELLED'` and 日期/月份命中 |
| DASH-14 | 会议室占用时长 | 在筛选范围内，该会议室所有有效预约的 `(end_time - start_time)` 之和 | 分钟（基础单位），展示可换算为小时 | `SUM(TIMESTAMPDIFF(MINUTE, start_time, end_time))` |
| DASH-15 | 部门预约场次 | 在筛选范围内，该部门作为预约归属部门的有效预约记录条数 | 场（条） | `COUNT(*)` where `dept_id = ?` and `status != 'CANCELLED'` and 日期/月份命中 |
| DASH-16 | 部门占用时长 | 在筛选范围内，该部门所有有效预约的 `(end_time - start_time)` 之和 | 分钟（基础单位），展示可换算为小时 | `SUM(TIMESTAMPDIFF(MINUTE, start_time, end_time))` |

### 5.4 占用时长的统一口径

| 规则编号 | 规则 |
| :-- | :-- |
| DASH-17 | 占用时长 = `end_time - start_time`，以 **分钟** 为基础单位存储与计算（整数），避免浮点误差。 |
| DASH-18 | `start_time` 与 `end_time` 均为预约记录中存储的时间（同一天内的时间，MVP 不跨天）。 |
| DASH-19 | 排除已取消（CANCELLED）的预约，不计入场次与时长。 |
| DASH-20 | 占用时长统一按 **原 `end_time - start_time`** 计算。提前结束（ENDED）**不更新** `end_time`，也**不引入** `actual_end_time` 等额外字段；提前结束仅改变状态，不影响占用时长的统计口径。（已按决策A/评审建议4修订：删除"按实际 end_time/更新字段"表述） |
| DASH-21 | 未开始（PENDING）但已到预约时间的预约若状态尚未流转为 ACTIVE（因定时任务延迟），仍按记录的 `end_time - start_time` 计入时长（口径以记录字段为准，不二次推断）。ACTIVE 态同样按记录字段 `end_time - start_time` **全量计入**，不按当前时刻截断。（已按评审建议10补充） |
| DASH-22 | 展示层单位换算：图表轴与指标卡默认展示「分钟」；当单值超过 60 分钟时，Tooltip/指标卡可附加「X 小时 Y 分钟」友好展示；月份维度因数值较大，Y 轴单位可选择「小时」（保留 1 位小数）以避免轴标签过长。 |
| DASH-23 | 时长结果为整数分钟；若出现 `end_time <= start_time` 的异常数据，按 0 计入并记录告警日志，不抛异常阻断统计。 |

### 5.6 实时性与缓存

| 规则编号 | 规则 |
| :-- | :-- |
| DASH-33 | 看板查询走 Redis 缓存，相同筛选参数的查询结果在缓存有效期内直接返回，减少数据库聚合压力。 |
| DASH-34 | 缓存键格式：`dashboard:{dim}:{dateKey}`，其中 `dim` 为 `day` 或 `month`，`dateKey` 为 `yyyy-MM-dd`（日维度）或 `yyyy-MM`（月维度）。示例：`dashboard:day:2026-10-27`、`dashboard:month:2026-10`。 |
| DASH-35 | 缓存值为序列化后的统计结果 JSON（含四组指标：会议室场次、会议室时长、部门场次、部门时长，及对应主数据名称列表）。 |
| DASH-36 | 缓存过期策略：日维度 TTL 默认 5 分钟；月维度 TTL 默认 15 分钟（月份数据变化相对平缓，可适当延长）。TTL 可通过配置调整。 |
| DASH-37 | 缓存失效（主动清除）时机：当发生预约新增、取消、提前结束等改变 `reservation` 数据的写操作时，按受影响的 `reserve_date` 主动删除以下缓存键集合，保证下次查询拿到最新数据：①`dashboard:day:{yyyy-MM-dd}`；②`dashboard:month:{yyyy-MM}`；③`dashboard:empty:day:{yyyy-MM-dd}`；④`dashboard:empty:month:{yyyy-MM}`。（已按评审建议1补充：显式列出失效 key 含空结果 key） |
| DASH-38 | 缓存击穿/穿透防护：对查询结果为空的情况也缓存一个「空结果」标记（短 TTL，如 1 分钟），避免空数据被反复回源；同时限制单用户对相同 key 的并发回源：互斥锁 key 格式 `dashboard:lock:{dim}:{dateKey}`（dim 为 day/month），TTL 3~5 秒，持锁失败时回退为短暂等待重试（默认 200ms 内重试一次）或直接回源并接受极少量重复查询，不阻塞用户。（已按评审建议7补充：明确锁 key、TTL、回退策略） |
| DASH-39 | 缓存异常容错：Redis 不可用时，看板查询降级直连数据库，不向用户报错；记录告警日志。 |
| DASH-40 | 时区一致性：`dateKey` 以服务器时区（Asia/Shanghai）格式化，缓存与统计的日期边界保持同一时区。 |
| DASH-41 | 刷新按钮语义：前端「刷新」按钮点击后，请求携带 `bypassCache=true` 标记；后端忽略对应缓存直接回源数据库，并将最新结果回填缓存（覆盖旧值并重置 TTL），同时清除该 key 的空结果标记。前端对相同参数的重复点击在 3 秒内做防抖，仅首次发起请求。（已按评审建议2补充） |
| DASH-42 | summary 汇总字段口径：`totalCount` = 范围内有效预约（status != CANCELLED）总条数；`totalMinutes` = 范围内有效预约 `SUM(end_time - start_time)` 总分钟数；`roomCount` = 会议室主数据全量条数（与图表 X 轴类别数一致，含 0 场者）；`deptCount` = 部门主数据全量条数（与图表 X 轴类别数一致，含 0 场者）。`totalCount` 应等于 `roomStats.count` 之和，也应等于 `deptStats.count` 之和；`totalMinutes` 应等于 `roomStats.minutes` 之和，也应等于 `deptStats.minutes` 之和。（已按评审建议3补充） |

## 6. 指标定义汇总

| 指标 | 统计对象 | 维度 | 公式 | 单位 | 排除项 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 会议室预约场次 | 会议室 | 日期/月份 | `COUNT(reservation)` where room_id 匹配 and status != CANCELLED | 场 | CANCELLED |
| 会议室占用时长 | 会议室 | 日期/月份 | `SUM(end_time - start_time)` where room_id 匹配 and status != CANCELLED | 分钟（可换算小时） | CANCELLED；异常(end≤start)按 0 |
| 部门预约场次 | 部门 | 日期/月份 | `COUNT(reservation)` where dept_id 匹配 and status != CANCELLED | 场 | CANCELLED |
| 部门占用时长 | 部门 | 日期/月份 | `SUM(end_time - start_time)` where dept_id 匹配 and status != CANCELLED | 分钟（可换算小时） | CANCELLED；异常(end≤start)按 0 |

口径说明：

- 「场次」即有效预约记录条数，一条预约计为 1 场。
- 「占用时长」基于记录的**原** `start_time / end_time` 字段计算；提前结束（ENDED）不更新 `end_time`、不引入 `actual_end_time`，按原 `end_time - start_time` 计算。（已按决策A修订）
- 部门归属以预约记录上的 `dept_id` 为准（预约发生时所属部门）。
- 会议室归属以预约记录上的 `room_id` 为准。
- 看板用存储态 `status` 判定，不走 `computeStatus`；`PENDING / ACTIVE / ENDED` 均计入，仅 `CANCELLED` 排除。（已按决策B补充）

## 10. 边界条件

1. **未来日期/月份**：允许选择，但通常无有效预约，展示空数据态；不禁止选择未来范围。
2. **极早历史日期**：系统上线前的日期无数据，展示空数据态；不限制最早可选日期。
3. **跨天预约**：MVP 限定单日内起止时间，`reserve_date` 即为业务日期；月份维度按 `reserve_date` 落在月内统计，不涉及跨月拆分。
4. **时区**：所有日期/月份边界与 `dateKey` 以服务器时区 Asia/Shanghai 计算。
5. **CANCELLED 不计入**：已取消预约既不计入场次，也不计入时长；统计 SQL 需显式 `status != 'CANCELLED'`。
6. **ENDED 提前结束**：占用时长统一按原 end_time - start_time 计算，提前结束不更新 end_time，也不引入 actual_end_time 额外字段；提前结束仅改变状态为 ENDED，不影响占用时长口径。（与决策A统一）
7. **会议室/部门被删除**：MVP 不提供物理删除；如未来扩展软删，历史统计仍按 `id` 关联，主数据名称缺失时兜底「未知会议室/未知部门」。
8. **空数据缓存**：空结果也缓存，TTL 1 分钟；预约写操作触发缓存失效时，对应空结果 key 一并清除。
9. **并发刷新**：相同 key 并发回源由简易互斥或短 TTL 容忍；不要求强一致。
10. **Redis 故障**：降级直连数据库，前端无感知；TTL 配置缺失时使用默认值并在日志告警。
11. **维度切换时数据一致性**：切换维度后请求参数随之变化，缓存 key 不同，互不污染。
12. **数值过大**：月份维度场次/时长可能较大，Y 轴自动分轴；时长超过 60 分钟按 7.3 规格可切小时展示。
13. **主数据为空**：若会议室或部门主数据表为空，图表展示空态而非报错（前端能渲染空数组）。
14. **异常时长数据**：`end_time <= start_time` 的记录按 0 计入并告警，不阻断统计。
15. **权限边界**：员工与管理员看到完全相同的看板数据；不存在「仅看本人/本部门」的过滤逻辑。

## 12. 与其他分册的边界

- **预约管理**：预约的状态机（PENDING/ACTIVE/CANCELLED/ENDED）、`end_time` 在提前结束时的更新规则、冲突校验由预约分册定义；本分册仅消费这些字段进行统计，并约定 CANCELLED 不计入、提前结束 ENDED 按原 end_time - start_time 计入占用时长。
- **用户与权限**：本分册看板接口要求 JWT 有效但不要求 ADMIN 角色；越权防护、登录鉴权细节由用户与权限分册定义。
- **会议室主数据**：会议室名称、是否启用等由会议室分册定义；本分册按主数据全量展示（含 0 场），主数据变更（如新增会议室）下次查询即生效。
- **部门主数据**：部门名称与新增/停用由相关分册定义；本分册按主数据全量展示。
- **非功能性需求**：性能（聚合查询响应时间、缓存命中率目标）、日志规范、部署等由非功能分册承载；本分册仅给出缓存策略与降级要求的功能性约束。
